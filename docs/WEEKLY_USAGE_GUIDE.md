# Career Evidence — Personal Usage Guide

Private workspace → **Career Evidence** (`/workspace`). Everything stays private unless you
manually use an approved, public-safe version.

> **Rule:** Do not log activity just to make the dashboard look busy. Record evidence that
> helps explain professional capability and commercial impact.

## Weekly — 10–15 minutes
1. **Record BD activity numbers** — one entry per standard metric (accounts researched,
   decision-makers engaged, positive responses…), with the right context and role.
2. **Record meaningful outputs / outcomes** — qualified opportunities, meetings, proposals.
3. **Record achievements immediately** — while the facts are fresh, in your own words,
   without client names or confidential figures.
4. **Add your contribution** — what *you* did, not what the team did.
5. **Add verification when available** — move to Supported / Verified only with a real
   source (report, letter, manager confirmation) and name it.
6. **Check one evidence gap** — Analytics → *Evidence gaps*; pick one to close next week.

## Monthly — 20–30 minutes
1. **Review strongest evidence** — CV-ready tab, top entries.
2. **Upgrade evidence status where justified** — never without proof.
3. **Create public-safe versions where useful** — anonymised; approve only what you would
   genuinely use externally.
4. **Build / update one STAR interview story** — Situation · Action · Result · Lesson.
5. **Review CV-ready evidence** — note the missing measurements and start capturing them.
6. **Export a backup** — Evidence log → Backup → *Export JSON*; store it somewhere safe.

## Quarterly
1. **Review which capabilities now have strong evidence** — Analytics → *By capability*.
2. **Identify capabilities with weak or no evidence** — these are your weakest CV claims.
3. **Identify your strongest CV / LinkedIn / interview evidence** — approved, public-safe entries.
4. **Review progress by role, market and industry** — use the Analytics filters.
5. **Decide whether any platform feature is genuinely needed** — only if real usage shows a gap.
